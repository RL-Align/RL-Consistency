The inherited ROCr mask selected Devices 2/3; it was replaced only in task processes before GPU initialization. The initial probes established the logical BDF mappings and `rocm-smi` compute allocation, but **did not establish strict device isolation**. Later `/proc/PID/fdinfo` inspection found DRM descriptors and 164 KiB VRAM records for each excluded Device 0–3 in task workers despite the UUID filter. Those early probes are not accepted as a strict isolation pass.

All task GPU drivers were interrupted using their recorded PIDs; their Ray workers exited. The final process query contains only the preexisting external jobs. No external process was killed or reset. The interrupted proxy and full conversion both have exit code 1.

A process-local Landlock ABI 4 wrapper was implemented to deny unapproved DRM nodes before importing the GPU runtime. Negative opens of the Device 0–3 render nodes return permission errors, and permitted Device 4/5 nodes open successfully. The installed HSA runtime nevertheless tries to open `renderD129` (physical Device 0) during initialization; denying it produces `hipErrorNoDevice`. This reproduces with and without the secondary HIP/CUDA masks. Three restricted probes preserve the failure. The wrapper never grants extra access or changes shared device permissions. Its intended inherited restriction follows the [Linux Landlock process model](https://docs.kernel.org/userspace-api/landlock.html).

The required next prerequisite is a runnable environment that both prevents excluded-node access and initializes the authorized GPUs. A task-private device-node view or a separately built and verified runtime may address it, but neither is validated here. Namespace creation is also unavailable in this container (`bwrap: No permissions to create a new namespace`). Do not weaken the zero-allocation requirement or treat the small DRM records as an allowed exception.
